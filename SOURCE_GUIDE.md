# Где изменять код

| Пакет / путь | Назначение |
| --- | --- |
| `greed.client.GreedClient` | Запуск клиента, регистрация событий, горячих клавиш и ресурсов |
| `greed.client.module` | Базовый `Module`, `ModuleManager` и категории |
| `greed.client.module.combat/movement/render/player/misc` | Реализации модулей по категориям |
| `greed.client.setting` | Числовые, текстовые, цветовые и другие настройки |
| `greed.client.event` | `EventBus`, слушатели, приоритеты, события игры |
| `greed.client.command` | Команды и их диспетчер |
| `greed.client.ui` | Главное меню, экраны, анимации интерфейса |
| `greed.client.ui.hud` | HUD, положение элементов, стили и уведомления |
| `greed.client.ui.setting` | Отрисовка и ввод настроек |
| `greed.client.ui.panel` | Панели аккаунтов, модулей, AutoBuy и пресетов |
| `greed.client.render` | Шрифты, GPU-пайплайны, данные и состояния отрисовки |
| `greed.client.cosmetic` | Загрузка и отрисовка косметики, модели Bedrock |
| `greed.client.scripting` | Lua API и сценарии поворота |
| `greed.client.storage` | Конфигурации, аккаунты, макросы и очереди задач |
| `greed.client.util` | Вспомогательные операции, время, анимации и ввод |
| `greed.mixin` | Связь мода с Minecraft через 87 mixin-классов |
| `assets/greed` | Шрифты, текстуры, шейдеры, звуки |

Для изменения модуля откройте соответствующий `*Module.java`. При добавлении нового модуля используйте существующие `Module`, `ModuleInfo` и настройки и зарегистрируйте его в `ModuleManager`. UI открывается правым Shift, если пользователь не изменил горячую клавишу.

Для главного меню смотрите `MainMenuScreen` и `WelcomeScreen`; для ClickGUI — `ClickGuiScreen`, `SettingRenderContext` и классы `*SettingRenderer`. HUD настраивается через `HudManager`. MSDF-шрифты загружают `FontRegistry`, `FontAtlasLoader` и `FontAtlas`; расположение ресурсов соответствует оригинальному JAR. `PipelineWarmup` начинает компиляцию после закрытия загрузочного overlay, когда Minecraft уже применил исходники шейдеров.

# Что восстановлено

Восстановлены Java-классы, вложенные типы, строковые конкатенации, generics и ресурсы из входного архива. Minecraft API переведён из intermediary-имён в Yarn. Для перегруженных методов mixin-инъекции получили полные дескрипторы. Исправлены проблемы Java-декомпиляции: области переменных в `switch`, стёртые типы в mixin и вложенные классы.

Названия подобраны по реализации, аннотациям модулей, шейдерам, полям данных и местам вызова. Имена не являются доказательством исходного замысла автора. Технические имена внутри сложных реализаций оставлены там, где значение ещё не установлено. Все эти реализации находятся в исходниках и доступны для изменения; бинарных заглушек модулей нет.

`ru.dreamix` и `com.greed.lib.discord` сохранены отдельно, поскольку их имена связаны с JNI/JNA. В JAR нет реализации шести `native`-методов. `ProfileAPI.create` уже в оригинале перехватывает отсутствие native-библиотеки и создаёт локальный профиль; эта ветка сохранена. Воссоздать исходный нативный код только по Java-декларациям невозможно.

Удалён только ставший ненужным bootstrap строковых конкатенаций. IRC, сетевые службы, торговые функции и косметика сохранены как в GREED. Доступность внешнего каталога косметики зависит от сервера: во время проверки он возвращал HTTP 403. Полная проверка каждого модуля и внешнего сервиса не выполнялась.

# Проверки и отчёты

`recoveryChecks` проверяет числовые настройки, преобразования Float/Double, выбор вариантов, анимации, подписку/отписку и приоритет событий, а также исходную ветку локального профиля. Отчёты восстановления лежат в `recovery`: карта исходных классов, переименования, пути источников и проверка сохранения ссылок Java. Эти отчёты не участвуют в сборке.

Утилиты декомпиляции использовались однократно, по этапам. Для обычной работы с проектом они не нужны; повторная декомпиляция поверх изменённых `.java` перезапишет ручные правки. Gradle-сборка использует только `src`, настройки сборки и опубликованные зависимости.

Итоговая проверка: Gradle `build` и `recoveryChecks` прошли, `runClient` запущен и штатно завершён с кодом 0; загрузились все 7 MSDF-шрифтов, ошибок компиляции шейдеров в логе нет. Новый мир и все сочетания включённых модулей после окончательной перестройки пакетов отдельно не проверялись.
