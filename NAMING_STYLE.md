# Стиль переименования (greed/client)

Файл описывает, как технические имена декомпилятора заменяются на осмысленные.
Используется для ручных правок и для агентов, которые обрабатывают файлы.

## 1. Что переименовывать

### 1.1 Локальные переменные и параметры — обязательно все
Шаблон: `\blocal\d+_\d+\b` (например `local3209_1`, `local6584_2`).
В файле после правки не должно остаться ни одного такого имени.

### 1.2 Приватные (`private`) и package-private поля
Только если поле не используется в других файлах. Шаблоны-заглушки:

- `intVal\d*`, `floatVal\d*`, `doubleVal\d*`, `longVal\d*`, `boolVal\d*`
- `strVal\d*`, `strValArray\d*`, `string\d*`
- `flag\d*`
- `vec3d\d*`, `vec2f\d*`, `vec4f\d*`
- `timeMillis\d*`, `nanoTime\d*`
- `list\d*`, `map\d*`, `set\d*`, `array\d*`
- `object\d*`, `obj\d*`, `value\d*`

### 1.3 Приватные/package-private методы
Только если метод не вызывается из других файлов. Шаблоны-заглушки:

- `processData\d*`, `updateState\d*`
- `matchesCriteria\d*`, `checkState\d*`
- `computeInt\d*`, `computeFloat\d*`, `computeDouble\d*`, `computeLong\d*`
- `getNested\d+`, `renderElement\d*`
- `handle\d*`, `apply\d*`, `resolve\d*`, `perform\d*`
- `init\d*`, `draw\d*`, `render\d*`

## 2. Что не переименовывать

- публичные и `protected` члены — их сначала отдельно правят по всему проекту;
- имена Minecraft/Yarn, JDK, JOML и других библиотек;
- уже осмысленные имена (например `bufferAllocator`, `modeSetting`);
- строковые литералы, комментарии, имена пакетов и классов.

Если сомневаешься, используется ли `package-private`/`public` член вне файла —
проверь поиском по `src/main/java` и при наличии внешних ссылок не переименовывай.

## 3. Правила имён

- `lowerCamelCase`, английский, без транслита.
- Имя отражает смысл и единицы измерения:
  - геометрия: `viewportWidth`, `viewportHeight`, `minX`, `maxX`, `centerX`, `radius`;
  - рендер: `alpha`, `progress`, `scale`, `cornerRadius`, `thickness`, `blurRadius`;
  - игрок: `hurtTimeFraction`, `health`, `entity`, `target`;
  - время: `startTimeMillis`, `lastUpdate`.
- Если смысл неясен из кода — берётся имя по типу (`blockPos`, `matrixStack`,
  `text`, `amount`), с уточнением по месту использования.
- Уникальность в пределах файла: при коллизии добавляются суффиксы `2`, `3`, ...
- Одно и то же имя используется во всех вхождениях одной переменной.

## 3.1. Внешние вызовы (важно)

При переименовании приватного/локального метода переименовывай только его
**объявление** и вызовы, которые точно относятся к этому же классу:
`this.method(...)` или неквалифицированный `method(...)`.

НЕ трогай вызовы через другой объект или класс — это методы других классов,
даже если имя совпадает: `other.processData(...)`, `AnimatedValue.processData(...)`,
`SomeClass.computeInt(...)`. Иначе ломается компиляция (или тихо меняется смысл).

## 4. Технические требования

- Меняются только имена. Логика, форматирование, литералы и аннотации не трогаются.
- Никаких `local\d+_\d+` не остаётся.
- Файл остаётся синтаксически корректным Java.
- Gradle/компиляция запускаются централизованно, не в рамках обработки файла.
